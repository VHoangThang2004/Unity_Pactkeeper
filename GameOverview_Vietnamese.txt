1. TỔNG QUAN GAME
================================================================================

Tên project : SRPG-SRPG
Thể loại    : SRPG (Strategy RPG) — PvP chiến thuật theo lưới ô (grid)
Engine      : Unity + Unity Netcode for GameObjects (UTP transport)
Kiến trúc   : Server-authoritative (server quyết định logic, client chỉ hiển thị)

Điểm khác biệt so với SRPG turn-based cổ điển:
- KHÔNG phải "mỗi lượt 1 unit di chuyển rồi hết lượt".
- Dùng hệ thống TIMELINE + INSTANT: thời gian trôi liên tục, unit "sẵn sàng"
  khi bộ đếm step về 0, sau đó hai đội xen kẽ ra quyết định trong cửa sổ thời gian.

Chế độ chơi hiện có:
- PvP (chính) — ghép trận 1v1, mỗi bên tối đa 5 unit
- Story — đang stub/WIP (có placeholder scene, chưa hoàn thiện)

Meta-game (ngoài trận):
- Đăng nhập (Google / Steam / Dev login)
- Quản lý đội hình 5 slot
- Cấu hình từng unit (skill, vũ khí, trinket)
- Gacha (rút unit / weapon / trinket / gems)
- Xem lịch sử trận đấu

Trong codebase KHÔNG có class tên "Actor" hay "Role" cho gameplay.
"role" chỉ xuất hiện trong response đăng nhập backend (LoginResponse.role).

Hệ thống dùng 3 khái niệm chính:

  CurrentSkillPoint, MaxSkillPoint
  DamageMultiplier (%), DamageReduction (%)

  CurrentStep, NextStep, CurrentStepBase

Effect/buff trong trận có thể thay đổi stats tạm thời qua UnitRecalculator.

5. CƠ CHẾ GAMEPLAY — TIMELINE & INSTANT
================================================================================

File lõi: Assets/Scripts/Server/ServerTimelineManager.cs
Config   : Assets/Data/Shared/PvPMatchConfig.asset

──────────────────────────────────────────────────────────────────────────────
5.1. Khái niệm Instant
──────────────────────────────────────────────────────────────────────────────

Một trận gồm nhiều "instant" (bước thời gian), tối đa 150 instant (config).
Mỗi instant có 2 phase:

  FLOWING  — thời gian trôi, unit tick step, buff tick, có thể regen SP
  PAUSED   — có unit ready → hai đội xen kẽ ra lệnh trong cửa sổ chờ

Tham số PvP (PvPMatchConfig.asset):
  maxInstant                        = 150
  instantDuration                   = 0.3 giây (visual pacing giữa instant)
  actWaitWindowPerInstantPerReadyUnit = 15 giây (cửa sổ chờ mỗi unit ready)
  maxWaitDurationMultiplier         = 5
  overtimePerTeam                   = 200 giây (thời gian dự trữ/overtime)
  conseRegenCap                     = 5 (số instant không ra lệnh trước khi +1 SP)
  effectsChangedWaitDuration        = 1 giây

──────────────────────────────────────────────────────────────────────────────
5.2. Hệ thống Speed / Step (giống CT — Charge Time)
──────────────────────────────────────────────────────────────────────────────

Mỗi unit có Speed. Server map Speed → khoảng step cần chờ trước khi ready.
Config: Assets/Data/Server/SpeedConfig_PVP_Patch1.asset

Ví dụ:
  Speed 0–109   → 10 step
  Speed 110–119 → 9–10 step
  Speed 120–129 → 9 step
  Speed 130–139 → 8–9 step
  Speed 140–149 → 8 step
  Speed 150–159 → 7–8 step

Mỗi instant FLOWING: CurrentStep giảm 1. Khi CurrentStep == 0 → vào Ready Queue.

──────────────────────────────────────────────────────────────────────────────
5.3. Vòng lặp chính mỗi Instant
──────────────────────────────────────────────────────────────────────────────

1. FLOWING
   - Regen SP (nếu unit không ra lệnh đủ conseRegenCap instant liên tiếp)
   - Tick step tất cả unit
   - Tick duration buff/effect
   - Cập nhật Ready Queue
   - Broadcast tick hoặc snapshot

2. Kiểm tra kết thúc sớm:
   - Cả hai đội pass 3 instant liên tiếp (không có unit ready mới) → hết trận
   - Chỉ còn 1 đội còn unit sống → hết trận

3. INSTANT PAUSED — Decision Loop
   - Hai đội xen kẽ (FlaggedTeamId xác định đội đi trước)
   - Đội active có WaitDuration = 15s × số unit ready của đội đó
   - Player gửi quyết định qua Netcode:
       ActivateAction — dùng skill lên ô mục tiêu
       Wait           — bỏ lượt unit đó trong instant này
   - Skill resolve theo InstantType (xem mục 6)

4. Cuối instant:
   - Resolve effect NonInstant (theo thứ tự speed)
   - Apply step cost sau khi dùng skill
   - Broadcast snapshot
   - CurrentInstant++

5. Hết 150 instant → trận kết thúc (theo số unit còn sống nếu hòa)

──────────────────────────────────────────────────────────────────────────────
5.4. Skill Point (SP)
──────────────────────────────────────────────────────────────────────────────

- Mỗi skill có skillPointCost (0 hoặc 1+)
- Nếu unit không ra lệnh trong instant, ConsecutiveRegenInstants tăng
- Sau conseRegenCap (5) instant liên tiếp không ra lệnh → +1 SP, reset counter
- Unit đã ra lệnh trong instant → reset ConsecutiveRegenInstants

──────────────────────────────────────────────────────────────────────────────
5.5. Điều kiện thắng / thua
──────────────────────────────────────────────────────────────────────────────

Trận kết thúc khi:
  a) Một đội bị wipe (không còn unit sống)
  b) 3 instant liên tiếp không có unit mới ready (cả hai đội pass)
  c) Đạt maxInstant (150)

Xác định thắng: đội còn nhiều unit sống hơn.
Nếu bằng nhau → winnerId rỗng (hòa).

Server gọi ReportResult() về backend, sau đó shutdown Netcode.

10. GHÉP TRẬN & NETWORKING
================================================================================

──────────────────────────────────────────────────────────────────────────────
10.1. Matchmaking flow (Client)
──────────────────────────────────────────────────────────────────────────────

File: Assets/Scripts/Client/MatchmakingManager.cs

1. Player bấm Find Match
2. POST /api/match/queue/join (JWT header)
3. Poll GET /api/match/queue/status mỗi 3 giây
4. Khi status == "matched":
     - Lưu matchId, serverIp, serverPort vào PlayerSession
     - Load scene 5_ClientMatch
5. ClientController kết nối Unity Transport tới game server

Hủy queue: DELETE /api/match/queue/leave

──────────────────────────────────────────────────────────────────────────────
10.2. Game Server startup (Backend → Headless Unity)
──────────────────────────────────────────────────────────────────────────────

Backend spawn process:
  SRPG_SERVER.exe -server -matchId <guid> -port <port> -batchmode -nographics

ServerBootstrap:
  - Parse -port (default 7777)
  - Start Netcode server trên 0.0.0.0:port
  - Load scene 4_Lobby

ServerBackendClient (trên game server):
  1. Login server credentials → POST /api/auth/login
  2. GET /api/match/{matchId}/info
  3. GET /api/match/{matchId}/loadouts
  4. IsReady = true

LobbyManager:
  - Chờ backend ready
  - Poll số client kết nối mỗi 1 giây
  - Đủ 2 player → load 5_ServerMatch
  - Timeout 120 giây → shutdown + PATCH status cancelled

──────────────────────────────────────────────────────────────────────────────
10.3. Xác thực kết nối client
──────────────────────────────────────────────────────────────────────────────

File: Assets/Scripts/Server/ServerConnectionManager.cs

- Client gửi JWT trong ConnectionData (payload Netcode)
- Server decode playerId qua TokenHelper
- Chỉ approve nếu playerId khớp player1 hoặc player2 trong loadout
- MatchIdentityRegistry map clientId ↔ playerId

──────────────────────────────────────────────────────────────────────────────
10.4. Đồng bộ trong trận (SyncedBridge)
──────────────────────────────────────────────────────────────────────────────

Client → Server:
  RequestInitialStateServerRpc   — xin snapshot ban đầu
  SendDecisionServerRpc          — gửi quyết định (unit, target, skill, Wait/Action)

Server → Clients:
  SpawnUnitClientRpc
  BroadcastTimelineTickClientRpc — tick nhẹ khi không có thay đổi lớn
  SendSnapshotToClientRpc        — full snapshot + resolve data

ClientMatchSession state machine: Idle / Syncing / Resolving
